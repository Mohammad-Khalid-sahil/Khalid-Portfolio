### Additional auth finding confirmed during final review

- **High — access-token revocation window:** `backend/src/config/env.js` defaults `JWT_EXPIRES_IN` to `1d`. `backend/src/controllers/authController.js` logout clears the stored refresh-token hash, while `backend/src/middlewares/auth.js` verifies access JWT signature/expiry and reloads the user but has no per-token revocation check. Thus logout invalidates refresh and the browser clears its in-memory token, but an already copied access token can still authorize requests until its configured expiry. The focused auth tests verify expiry rejection and refresh logout invalidation, not immediate access-token revocation. Consider a shorter access-token lifetime and/or a revocation/session-version mechanism; choose the trade-off before changing session behavior.

## Phase 1 — Admin session revocation and refresh rotation (2026-10-12)

### Decision and pre-change finding

The owner chose **account-wide logout**. This matches the existing one-refresh-token-hash-per-user model; independent per-device sessions would require a different persistence model and were not introduced. The confirmed defect was that logout cleared only the refresh hash while protected routes accepted copied access JWTs until expiry (default `1d`). Refresh rotation read and then saved the token hash in separate operations, allowing simultaneous uses to race.

### Minimal remediation

- Added `sessionVersion` (default 0) to the existing User document. New access and refresh tokens carry `sv`; protected middleware compares it with the current user version. Old tokens without `sv` are treated as version 0, and atomic queries account for legacy MongoDB documents where the field is absent; no migration is required.
- Logout atomically clears the refresh hash and increments the version, revoking all account sessions. Refresh performs a conditional atomic token-hash replacement, so a replay or concurrent second use fails. Login also conditionally writes against the version it read to avoid restoring a refresh session after a racing logout.
- Changed the default access-token lifetime to `15m`, validate JWT duration syntax/minimum, and derive refresh-cookie max-age from `JWT_REFRESH_EXPIRES_IN` (default `30d`). The access lifetime remains operator-configurable.
