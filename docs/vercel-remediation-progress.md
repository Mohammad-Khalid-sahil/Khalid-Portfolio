## Upload implementation (2026-10-12)

- **Design:** existing S3-compatible storage support is extended with short-lived SigV4 presigned `PUT` requests. File bytes go from the authenticated browser directly to storage, never through a Vercel Function. The URL signs MIME type and `If-None-Match: *` to restrict an object to one write. No Cloudinary dependency or schema change was needed.
- **Authorization/verification:** `POST /api/uploads/sign` requires existing `media:write`, validates filename/type/size (1 byte–5 MiB)/target, and issues a five-minute JWT bound to the authenticated owner and metadata. `POST /api/uploads/complete` checks owner, provider-reported size/type and initial file signature before creating the existing Media record. Replays are rejected. Invalid new content is deleted best-effort; existing media is not deleted on replay or DB-record failure.
- **Compatibility:** upload UI/components stay intact. Project uploads retain `{url, mediaId}` and media uploads retain the existing Media response envelope. Existing multipart routes remain for local development and compatibility; Vercel production refuses local-storage fallback. Local development continues using existing local disk and multipart routes.
